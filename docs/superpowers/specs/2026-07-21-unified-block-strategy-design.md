# 统一积木式执行策略设计

## 目标

把当前分离的“手动动作策略”和“自动执行策略”合并为一套可持久化、线性、可扩展的积木式策略系统。

系统必须满足：

1. 网页元素新增、编辑、删除后真实写入磁盘；刷新页面、关闭页面或重启服务后仍存在。
2. 所有需要选择网页元素的位置都读取同一份已持久化元素库。
3. 删除旧“策略管理”“添加动作”和旧九步自动策略界面，以统一策略列表和独立积木编辑页替代。
4. 策略只包含用户实际添加的动作；未添加的动作不得隐式执行。
5. 支持移动、点击、向上滚动、向下滚动、键盘输入、停止（等待）六类积木。
6. 支持内置拟人函数和用户录制的鼠标轨迹、键盘节奏 pattern。
7. 支持一次执行或循环执行。
8. 自动迁移已有手动策略和自动策略。

## 当前问题与根因

`saveBrowserElementFromDialog()` 当前只修改页面内存中的 `browserActionConfig.elements`，随后刷新列表和下拉框，没有调用 `/api/browser/action-config` 持久化接口。页面刷新后，`loadBrowserActionConfig()` 重新读取磁盘旧数据并覆盖内存，因此新增元素消失。

评论入口、输入元素和提交元素下拉框都来自同一内存元素字典。元素未落盘后，该字典在刷新时恢复为空或旧状态，因此三个下拉框也无法找到新元素。

当前界面和后端同时保留两套策略模型：

- `browser.action_strategies`：通用手动动作列表。
- `browser.auto_strategies`：固定滚动、评论入口、文案、输入、提交流程。

两套模型在点击、输入、滚动、等待等职责上重复，继续分别扩展录制 pattern 会进一步增加重复实现。

## 总体架构

采用单一 Python Playwright 执行引擎和单一积木策略模型。浏览器网关继续负责 AdsPower/CDP 连接、窗口调度、日志和 API；动作执行层负责参数校验与逐块执行；DOM 动作层负责具体鼠标、键盘和滚轮操作。

系统分为四个独立模块：

1. **网页元素库**：维护元素别名与 XPath/CSS 定位表达式。
2. **行为模式库**：维护鼠标轨迹 pattern 和键盘节奏 pattern。
3. **策略库**：维护策略元数据及有序动作积木。
4. **动作注册表与执行器**：定义动作类型、参数结构、校验器、执行函数和可引用 pattern 类型。

网关策略运行路径只调用 Python 动作实现。`browser/actions.js` 中的同名函数不作为第二套策略执行器；其中有用的参数和行为可移植到 Python 实现，但运行时不得跨语言重复分派。

## 持久化设计

### 独立保存边界

使用三个独立资源，避免某个未完成策略阻止元素或 pattern 保存：

- 网页元素：新增、编辑、删除时立即保存。
- 行为 pattern：录制完成并命名时立即保存。
- 执行策略：点击“保存策略”时保存完整策略。

建议 API 边界：

```text
GET/PUT /api/browser/elements
GET/PUT /api/browser/patterns
GET/PUT /api/browser/strategies

POST /api/browser/pattern-recordings/start
GET  /api/browser/pattern-recordings/{recording_id}
POST /api/browser/pattern-recordings/{recording_id}/stop
```

录制 API 可以按现有 Flask 路由风格调整命名，但必须保持元素、pattern、策略三个持久化边界独立。

### 保存事务

每次保存严格执行：

1. 前端提交完整资源数据。
2. 后端校验类型、范围、引用关系和 ID 唯一性。
3. 后端通过现有设置存储层原子写入配置文件。
4. 后端返回实际落盘后的规范化数据。
5. 前端用返回数据替换本地状态并重新渲染。
6. 仅在以上步骤全部成功后显示“已保存”。

保存失败时保留编辑内容，不关闭对话框或编辑页，并显示后端返回的具体原因。页面存在未保存策略修改时，刷新、关闭或离开页面前显示警告。

元素保存成功后，所有积木目标选择框必须立即从后端返回的元素数据重建。不得只把新选项临时插入某一个下拉框。

删除被策略引用的元素时拒绝删除，并返回引用策略名称和动作序号。删除被策略引用的 pattern 时采用同样规则。

### 配置结构

浏览器配置新增统一数据：

```json
{
  "browser": {
    "strategy_schema_version": 2,
    "action_elements": {
      "评论入口": "xpath=..."
    },
    "interaction_patterns": [
      {
        "id": "pattern_mouse_1",
        "name": "自然浏览轨迹",
        "type": "mouse",
        "data": {}
      }
    ],
    "block_strategies": [
      {
        "id": "strategy_1",
        "name": "评论发布",
        "run_mode": "loop",
        "loop_duration_minutes": [3, 5],
        "batch_size": 4,
        "actions": []
      }
    ]
  }
}
```

`run_mode=once` 时忽略 `loop_duration_minutes`。`run_mode=loop` 时，每个窗口在启动时从时长范围抽样一次，完整动作序列重复执行，达到截止时间后不再启动下一轮；已开始的单个动作允许完成。

## 动作注册表

每个动作类型注册以下内容：

- 稳定类型 ID。
- 中文显示名称。
- 参数 schema 和默认值。
- 后端校验器。
- Python 执行函数。
- 可引用的 pattern 类型。
- 前端参数编辑元数据。

前端从后端动作目录生成积木选择区和参数表单，避免新增动作时手工维护多套类型列表。动作目录只描述允许展示的字段，最终校验始终由后端完成。

### 移动 `move`

支持两种目标：

- 移动到网页元素：选择元素别名，运行时终点落在元素可点击区域内。
- 相对移动：配置横向、纵向移动比例；比例相对当前内容视口宽高。

轨迹来源：

- 内置函数：复用并参数化 `human_move_to()`、`human_move()` 的平滑曲线路径。
- 录制 pattern：引用鼠标 pattern ID。

参数包含目标模式、目标元素或相对位移、轨迹来源、持续时间或速度范围。移动动作只移动，不点击。

### 点击 `click`

参数包含目标元素、鼠标键、点击次数、按下时长、点击前后间隔和接近轨迹。点击目标必须引用元素库。

物理点击必然需要把指针接近目标。点击积木可以使用内置接近轨迹或鼠标 pattern；这是点击动作自身的定位过程。单独的移动积木用于无点击的浏览移动，不会被点击积木隐式插入策略列表。

执行复用 `human_click()`，并拆出可配置的移动与按键阶段。不得让键盘输入积木额外触发点击。

### 向上滚动 `scroll_up` 与向下滚动 `scroll_down`

参数包含单次距离、次数或次数范围、相邻滚动间隔和滚动后等待。方向由积木类型确定。执行复用现有 `page.mouse.wheel()` 和拟人等待逻辑。

旧自动策略中的滚动次数、滚动间隔、累计阈值和阈值后等待迁移为一个滚动积木及其后的停止积木，保持原有随机范围语义。

### 键盘输入 `keyboard_input`

参数包含：

- 目标输入元素。
- 内容来源：固定文本、全部文案随机、指定文案品牌。
- 输入节奏：内置随机间隔或键盘 pattern。

输入前使用 DOM focus 聚焦目标，不隐式点击。执行复用并参数化 `human_type()`。输入完成后继续使用现有输入值与页面回显校验。

内置节奏支持每字符最小、最大间隔。pattern 节奏保存按键间隔和按下时长，不保存字符。实际文本短于录制样本时选取连续片段；长于样本时从不同偏移继续采样并加入有限抖动，避免机械重复整段时间序列。

### 停止（等待）`pause`

“停止”表示等待指定时间后继续，不表示终止策略。参数支持固定时长或最小、最大随机范围，复用 `random_pause()`。

## 行为模式录制

### 录制入口

用户在模式库选择：

1. 已打开的 AdsPower 窗口。
2. 鼠标轨迹或键盘节奏类型。

网关通过当前 CDP 会话向目标页面注入隔离的悬浮控制条。用户在目标 AdsPower 网页窗口内点击“开始录制”；控制条切换为明显的录制状态。用户点击“结束录制”或按 `Ctrl+Shift+F10` 结束。悬浮控制条自身产生的鼠标和键盘事件不计入 pattern。

录制结束后，管理页展示时长、鼠标采样点数或键盘间隔数。用户命名并保存后立即持久化；取消则丢弃本次临时录制。

### 鼠标 pattern

鼠标 pattern 只保存轨迹与时间：

- 录制视口宽高。
- 归一化坐标或相对位移。
- 相邻采样点时间差。
- 总时长。

不保存点击目标、页面内容或绝对屏幕坐标。

回放相对移动时，按当前内容视口宽高缩放位移。回放移动到元素时，把录制轨迹变换到“当前指针到目标元素内部点”的起终点区间，保留相对曲率和时间节奏，并强制最后一点落在目标元素内。所有中间点裁剪到当前可视内容区，避免多窗口平铺后的轨迹越界。

### 键盘 pattern

键盘 pattern 只保存：

- 相邻有效按键的时间间隔。
- 按键按下时长。
- 样本总时长和样本数量。

不保存真实字符、组合输入内容、剪贴板内容、密码或输入框值。录制控制键和结束快捷键不进入样本。

### 录制失败

以下情况终止录制并禁止保存空数据：

- AdsPower 窗口关闭。
- CDP 会话断开。
- 页面导航导致注入上下文失效且无法重新挂载。
- 鼠标采样点或键盘间隔数低于最小有效样本数。

失败信息包含窗口、录制类型、阶段和原因。

## 管理界面

采用已确认的“列表页进入独立编辑页”布局。

### 顶层页面

页面从上到下包含：

1. 网页元素管理。
2. 行为模式库。
3. 执行策略列表。
4. 窗口选择与执行区。

删除旧“策略管理”“添加动作”“保存自定义策略”“读取已保存策略”控件，以及旧九步自动策略编辑区。

### 策略列表

每个完整策略显示为列表项或卡片，展示名称、一次/循环、动作数量和保存状态。支持新建、打开、重命名、删除。点击策略进入独立编辑页。

删除策略前要求确认；删除成功后立即持久化。策略 ID 保持不变，重命名只修改名称。

### 策略编辑页

顶部包含返回列表、名称、执行模式、循环时长、批量窗口数、重命名、删除、保存。

动作选择区展示六类积木。点击某个积木才把它添加到有序动作列表；未选择的动作不出现在策略中，也不执行。动作列表支持编辑、上移、下移和删除。每个动作只展示与自身类型相关的参数。

保存按钮只有在数据实际落盘后显示“已保存”。有未保存修改时显示明确状态，并在离开前警告。

## 执行流程

1. 读取并校验已持久化策略、元素和 pattern。
2. 启动或连接选中的 AdsPower 窗口。
3. 按现有流程同步目标页面和清理 Tab。
4. 对每个窗口建立独立执行上下文。
5. 严格按 `actions` 数组顺序执行积木。
6. 一次模式完成一轮后结束；循环模式在截止时间前继续下一轮。
7. 返回逐动作结果并写入浏览器操作日志。

任何积木失败后，当前窗口不执行后续积木，并记录策略 ID、窗口 ID、动作 ID、动作序号、动作类型、阶段和原始错误。其他窗口继续运行。配置引用错误在启动窗口前统一拒绝，避免产生部分副作用。

## 旧数据迁移

迁移必须幂等，并由 `strategy_schema_version` 控制，只在新版策略尚未生成时执行一次。

### 手动策略

`browser.action_strategies` 中的 `move`、`click`、`input`、`scroll_up`、`scroll_down`、`pause` 逐项转换为同类积木。固定输入文本和 `generated_comment` 内容来源保留。缺失的新参数使用注册表默认值。

### 自动策略

每个 `browser.auto_strategies` 项转换为：

1. 初始停止积木。
2. 向下滚动积木。
3. 阈值后停止积木。
4. 点击评论入口积木。
5. 键盘输入积木。
6. 点击提交积木。

名称、入口元素、输入元素、提交元素、文案品牌、批量窗口数、总执行时长及滚动随机范围尽量原样保留。自动策略迁移为循环模式。

若旧策略引用不存在的元素，不猜测替换；迁移后标记为“需要修复”，允许打开编辑，但禁止执行和保存为有效状态，直到用户补全。

新配置成功原子写入并设置版本号后才算迁移完成。首个版本保留旧字段作为只读回退数据，但界面和执行器不再写入或使用旧字段。策略 ID 冲突时使用稳定来源前缀生成新 ID，避免重复迁移产生副本。

## 校验和引用完整性

后端至少校验：

- 策略、动作和 pattern ID 非空且同类唯一。
- 策略名称非空。
- `run_mode` 只能为 `once` 或 `loop`。
- 循环时长和批量窗口数在允许范围内。
- 动作类型已注册。
- 动作参数符合类型 schema 和数值范围。
- 元素引用存在。
- pattern 引用存在且类型匹配。
- 键盘输入具有有效内容来源。
- 录制样本不含文本字段或绝对屏幕坐标。

前端校验只用于即时提示，不替代后端校验。

## 测试计划

采用 TDD，先写失败测试，再实现。

### 持久化

- 新增、编辑、删除元素后重新 GET 仍一致。
- 保存后重新创建 Flask 应用并重新读取配置仍一致。
- 策略和 pattern 采用相同重启读取测试。
- 后端写入失败时前端不得显示“已保存”，编辑内容不得丢失。

### 元素同步

- 新增元素后立即出现在所有目标元素下拉框。
- 重命名元素后引用安全迁移或明确阻止。
- 被策略引用的元素无法删除，并返回引用位置。

### 动作执行

- 六类积木分别验证参数、默认值和执行调用。
- 多积木严格保持数组顺序。
- 键盘输入不隐式点击。
- 停止积木等待后继续。
- 任一动作失败后当前窗口停止，其他窗口继续。
- 一次模式只执行一轮；循环模式遵守截止时间。

### 录制与缩放

- 手动开始和结束控制录制边界。
- 控制条事件不进入 pattern。
- 键盘样本不包含真实字符。
- 鼠标坐标归一化并按目标窗口缩放。
- 目标元素回放终点位于元素内部。
- 越界采样点被限制在可视区域。
- CDP 断开、窗口关闭和样本不足时拒绝保存。

### 迁移与界面

- 手动策略和自动策略迁移结果稳定且幂等。
- 缺失元素的旧策略进入“需要修复”状态。
- 旧策略管理、添加动作和九步自动策略控件不存在。
- 策略列表、独立编辑页、六类积木、保存状态和未保存警告存在。
- 完整 Python、Node 和页面测试套件无回归。

## 验收标准

1. 新增元素保存后，刷新页面和重启服务均不丢失。
2. 新增元素立即可用于所有动作的目标元素选择。
3. 页面只存在一套策略管理入口和一套积木执行模型。
4. 用户可以创建、打开、重命名、编辑、保存、删除完整策略。
5. 只有添加到列表中的积木会按可见顺序执行。
6. 六类积木均可独立配置参数并引用正确的既有 Python 动作函数。
7. 用户能在完整 AdsPower 页面内手动开始、结束鼠标或键盘 pattern 录制。
8. 鼠标 pattern 在多窗口小尺寸下正确缩放且不越界；键盘 pattern 不保存输入内容。
9. 一次和循环模式均按配置执行。
10. 旧策略自动迁移且不重复、不静默猜测缺失引用。
11. 所有“已保存”状态都有后端落盘结果作为依据。

## 范围外

- 不录制真实按键内容、密码、剪贴板内容或页面文本。
- 不保存绝对屏幕坐标。
- 不录制完整网页操作脚本；鼠标和键盘 pattern 仅作为积木参数。
- 不新增条件分支、并行分支、循环积木或脚本代码积木。
- 不把 Node 动作实现引入 Python 网关运行路径。
