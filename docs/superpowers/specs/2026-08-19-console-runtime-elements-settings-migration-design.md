# Console 运行环境、页面元素与系统设置迁移设计

## 目标

完成 Agent Console 的第二阶段界面收口：

- 将当前只有四项只读状态的“运行环境”并入“运行总览”，暂时取消独立一级入口。
- 将“页面元素”从 Browser V2 聚合页迁移为 Console 原生页面，同时保留现有页面点选器、元素校验和 revision 冲突保护。
- 将“系统设置”从旧根控制台迁移为 Console 原生页面，同时保留现有配置、密钥保护、健康检查和备份恢复语义。

本阶段解决的是页面归属、信息结构和 UI 一致性，不重写已有业务执行链。

## 已确认决策

1. 当前“运行环境”不具备独立模块的业务密度，应先并入“运行总览”。
2. `/console/runtime` 保留为兼容地址，但重定向到 `/console/overview#local-runtime`。
3. 侧边栏暂时移除“运行环境”。
4. 页面元素和系统设置必须直接渲染在 `console_base.html` 中，不使用 iframe，不继续跳转旧页面。
5. 页面元素复用现有 Browser V2 点选器、元素 Store 和 API，不恢复 Selector Probe 页面。
6. 系统设置复用现有 `/api/settings`、`/api/settings/status`、`/api/model-presets` 和代理池接口，不建立第二份配置存储。
7. 在真实后端契约存在前，不展示可点击的“排空后重启”或“同步到中控”按钮，也不伪造成功、同步或健康状态。

## 范围边界

### 本阶段包含

- 本机状态合并到运行总览。
- 页面元素 Console 页面及其共享前端控制器。
- 系统设置 Console 页面及其独立前端控制器。
- 原功能迁移所需的路由、模板、样式、测试和兼容入口。
- Browser V2 与旧控制台在迁移期间继续可访问。

### 本阶段不包含

- Agent 排空状态机、停止接单、Launcher Web 控制和重启进度 API。
- 页面元素同步到中控的协议、Outbox、冲突合并和中控存储。
- Selector Probe 管理界面。
- 浏览器执行策略、动作执行器、发布链路或采集链路重构。
- 删除旧 Browser V2 和旧设置页面。

“排空后重启”和“页面元素同步”是已确认的产品能力，但需要独立的后端契约设计。此阶段只保证 UI 不虚构这些能力；接入点分别限定为运行总览的本机状态区和页面元素页头操作区。

## 方案选择

### 方案 A：仅统一皮肤

保留现有重定向，只覆盖 Browser V2 和旧控制台的颜色、字体与间距。改动较小，但页面结构、控制器边界和交互方式仍然不统一，无法达到本次迁移的完成标准。

### 方案 B：复用原控制器，迁入 Console

将页面元素和设置工作区提取为可复用模板及前端控制器，由旧页面和新 Console 页面共用；运行环境先并入总览。该方案保留现有状态机和数据语义，同时完成页面归属与视觉统一。

### 方案 C：完全重写两个页面

只保留后端 API，重新实现页面元素和系统设置全部前端逻辑。代码最终更独立，但容易遗漏点选器会话、revision 冲突、密钥留空保持、配置恢复和配置所有权保护。

采用方案 B。

## 一、运行环境并入运行总览

### 页面结构

运行总览新增 `id="local-runtime"` 的“本机状态”区域，位置在总览关键业务指标之后、任务列表之前。区域保持业务界面密度，不增加概念说明。

首行展示四项真实可读状态：

- 本机网关：来自 `/api/status` 的请求可达性；文案不得把配置完整度表述为进程健康。
- 浏览器 Profile：来自 `/api/browser-v2/profiles` 的可用数量或连接失败状态。
- 数据采集服务：来自 `/api/tiktok-stats/status` 的 scraper 状态。
- 本机采集调度：来自 `/api/tiktok-stats/status` 的 worker 状态。

区域右上角提供“刷新”，并显示最后刷新时间。某个接口失败时，只将对应项标为“不可用”，其他结果继续展示。

### 导航与兼容

- `_dashboard_sidebar.html` 删除“运行环境”导航项。
- `/console/runtime` 返回到 `/console/overview#local-runtime` 的 302 重定向。
- 原 `console_runtime.html` 和 `console_runtime.js` 在没有其他引用后删除。
- 总览控制器吸收状态读取逻辑，但保持每个接口独立失败，不使用一个失败中断整块页面的 `Promise.all`。

### 独立模块恢复条件

只有以下真实能力全部具备时，才恢复“运行环境”一级入口：

- Agent 身份、版本、启动时间、中控连接和最近心跳。
- 各执行 Worker、外部依赖和能力自检。
- 当前负载、活动窗口、任务租约、待回传结果和阻塞原因。
- 停止接单、排空、取消排空、排空后重启及重启进度。
- 脱敏日志和诊断入口。

## 二、页面元素 Console 页面

### 路由与复用边界

- `/console/page-elements` 直接渲染 `console_page_elements.html`，`active_nav` 为 `page-elements`。
- 新模板继承 `console_base.html`。
- 页面元素工作区提取为共享 partial，使 Browser V2 元素标签和 Console 页面使用同一组稳定 DOM 标识。
- 点选器状态、请求封装、元素渲染、校验、重新点选和 revision 冲突处理从 `browser_v2.js` 提取到专门控制器。
- Browser V2 只负责装配该控制器，不复制元素业务逻辑。

### 页面布局

页面采用与其他 Console 模块一致的完整工作区：

1. 页头：标题“页面元素”，右侧主操作“开始点选”。
2. 点选工具区：测试 Profile、目标网址、开始、完成、取消和当前点选状态。
3. 筛选工具条：关键词、元素类型、状态；不展示无业务价值的统计说明。
4. 元素表格：名称、用途、类型、所属页面、定位器数量、状态、更新时间、操作。
5. 明细区：沿用已确认的行内全宽展开形式，紧邻所选记录展开，不使用右侧窄抽屉。

### 元素明细

明细只展示 Store 中真实存在的数据，并按以下逻辑分组：

- 基本信息：名称、用途、类型、启停状态、revision、创建和更新时间。
- 页面上下文：目标 URL、页面信息和 frame path。
- 语义信息：tag、role、accessible name、文本预览和关键 attributes。
- 定位信息：所有 locator、unique CSS、relative XPath、指纹及定位优先级。
- 几何与诊断：bounding box、点选诊断元数据、最近校验结果和错误。
- 证据：存在合法本地 evidence 路径时显示截图入口。

操作包括测试、重新点选、编辑、停用或启用、删除。删除和覆盖 revision 的操作使用明确确认；409 冲突不得覆盖服务器新版本。

### 点选器行为

- 必须保留启动、等待点击、捕获候选、连续保存、完成和取消的完整会话流程。
- Profile 不可用时禁用开始按钮，并在工具区显示具体原因。
- 点选会话活动期间禁止启动第二个会话。
- 页面离开时沿用现有活动会话保护。
- Selector Probe 不出现在新页面的导航、说明或设置中。

### 中控同步呈现

本阶段没有元素同步 API，因此页面不显示“已同步”“待同步”或“同步成功”等状态，也不提供同步按钮。元素数据结构和明细不做降级，确保独立同步协议能够传输完整记录。

## 三、系统设置 Console 页面

### 路由与数据边界

- `/console/settings` 直接渲染 `console_settings.html`，`active_nav` 为 `system-settings`。
- 新模板继承 `console_base.html`。
- 配置加载、状态检查、模型预设、保存和恢复继续调用现有 API。
- 新页面不直接读写 `config.json`，不建立新 Store。
- 账号级 Buffer Token、Profile 映射和代理分配继续归“账号与窗口”；系统设置只管理服务级配置。

### 页面布局

使用与其他 Console 页面一致的页头、卡片、表单控件、状态标签和按钮。页头下方显示配置健康摘要；主体使用顶部分类标签，一次展示一个分类；页面底部使用固定保存栏显示“未修改、存在未保存修改、正在保存、保存成功、保存失败”。

分类顺序为：

1. 代理与网络
2. 浏览器与 AdsPower
3. Buffer 与发布
4. R2 存储
5. 数据采集
6. 模型服务

### 配置归属

#### 代理与网络

- 单代理 host、port、username、password。
- 代理池 protocol 和批量代理文本。
- IP 检查接口和超时。
- 代理池总数、已分配和剩余状态，以及原有分页查看入口。

#### 浏览器与 AdsPower

- AdsPower base URL、API Key、默认分组。
- 浏览器 CDP URL、默认网址。
- 不在此处编辑页面元素、动作或策略定义。

#### Buffer 与发布

- Buffer 服务级 GraphQL 地址和发布超时。
- 发布队列间隔。
- 发布采样开关、采样间隔和最小视频年龄。
- 账号级 Token 与 Profile 映射不在本分类重复出现。

#### R2 存储

- Account ID、Account Token、Access Key ID、Secret Access Key。
- Bucket、Endpoint URL、公开访问域名和文件前缀。

#### 数据采集

- TikTok 采集 Cookie 的已配置状态、更新和连接验证，分别复用 `/api/tiktok-stats/settings/cookie` 与 `/api/tiktok-stats/settings/cookie/validate`。
- Cookie 输入保持密码字段，不回显已保存内容；留空且未主动提交时不清除原值。
- 采集 Worker 状态只读展示，不提供当前后端不存在的计划时间或 Worker 启停控件。
- 采集目标、手动导入、运行记录归“数据采集”模块，不在设置页重复管理。

#### 模型服务

- 默认模型。
- 模型列表中的 ID、供应商、启用状态、Base URL、API Key、模型名和调用模式。
- 模型候选项来自 `/api/model-presets`，同时保留自定义模型能力。

Selector Probe 配置不出现在新设置页。现有后端对相关配置所有权的 409 保护继续保留。

### 密钥与保存语义

- 密钥字段加载时保持空白，通过 `_secrets_configured` 显示“已配置”状态。
- 密钥留空表示保持原值，不能将空字符串误保存为清除密钥。
- 保存请求期间禁用重复提交。
- 切换分类不丢失未保存修改。
- 离开存在未保存修改的页面时给出浏览器离开确认。
- 400 显示字段或配置错误；409 显示配置所有权或 revision 冲突；网络错误保留表单内容并允许重试。
- “恢复最近备份”使用二次确认；恢复成功后重新加载配置和健康状态。

## 视觉一致性规则

三个区域统一使用 `console.css` 中的设计令牌和组件：

- 页面最大宽度、标题层级和页头间距与内容发布、动作库等新页面一致。
- 主按钮、普通按钮、危险按钮、状态标签使用同一语义颜色。
- 表格表头、行高、空状态、加载状态和错误状态使用同一组件规则。
- 表单标签、输入框、帮助文本和校验错误使用同一垂直节奏。
- 不使用 Browser V2 的独立页头、五标签导航或旧控制台的内联样式。
- 不增加右侧窄详情抽屉。

## 错误处理与降级

- 总览本机状态允许部分成功，单项失败不清空其他项。
- 页面元素加载失败时保留点选工具区和明确重试入口；点选会话错误显示服务返回的安全错误摘要。
- 系统设置状态接口失败不阻止读取配置；配置读取失败时禁止保存，避免用空表单覆盖现有配置。
- 所有密钥、代理凭据和 Token 不进入日志、DOM 文本、错误消息或测试快照。
- 旧页面在迁移验收前保留，作为兼容回退入口。

## 测试与验收

### Python 路由与 API 测试

- `/console/runtime` 重定向到 `/console/overview#local-runtime`。
- `/console/page-elements` 和 `/console/settings` 返回 200，不再重定向。
- 两个新页面包含共享侧边栏、正确 active nav、CSRF token 和对应页面根节点。
- 现有 Browser V2 元素 API、设置 API、密钥保持、恢复和 409 保护测试继续通过。

### JavaScript 单元测试

- 总览四项状态的成功、部分失败和刷新行为。
- 页面元素初始化、筛选、行内展开、点选会话、连续保存、重新点选、校验和 revision 冲突。
- 系统设置分类切换、脏状态、字段序列化、密钥保持、模型预设、保存失败和备份恢复。
- 所有动态文本继续通过 DOM `textContent` 或安全属性写入，禁止拼接未转义 HTML。

### 回归验收

- Browser V2 的执行中心、策略和历史不受元素控制器提取影响。
- 旧设置页在兼容期仍能加载和保存同一份配置。
- 内容发布、数据采集、账号与窗口继续读取相同配置。
- 新页面在常见桌面宽度和窄窗口下不出现横向页面溢出；表格允许自身滚动。

## 完成标准

- 侧边栏不再出现价值不足的独立“运行环境”入口。
- 运行总览可以查看并分别刷新四项真实本机状态。
- 页面元素和系统设置均在新 Console 内直接使用，不再跳转到旧工作台。
- 页面元素原有点选、保存、测试、重新点选和 revision 保护没有退化。
- 系统设置原有配置字段、密钥保持、健康检查、代理池、模型预设和恢复能力没有退化。
- 新页面与已迁移 Console 模块使用一致的信息密度和视觉组件。
- 页面不出现虚假的排空重启或中控同步能力。
