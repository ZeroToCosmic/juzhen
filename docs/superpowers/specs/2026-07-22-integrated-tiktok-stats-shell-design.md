# 数据统计融入自动化主控台设计

日期：2026-07-22

## 背景

当前“数据统计”从自动化主控台跳转到独立视觉页面。虽然统计功能完整，但侧栏、品牌和导航上下文消失，用户感觉进入了另一个系统。主控台还保留旧版发布数据统计面板，形成两个语义相近但数据来源不同的入口。

## 已确认方案

采用视觉方案 A＋A1：

- 主控台和 `/tiktok-stats` 使用相同页面外壳。
- 左侧栏始终展开，不提供收起功能。
- 数据统计保持独立 URL 和独立统计前端控制器，但视觉和导航属于同一主控台。
- 删除旧版主控台内嵌发布统计面板。

## 页面结构

### 共享侧栏

侧栏顺序保持：集中配置、账号花名册、代理配置、内容管理、发布管理、发布结果、数据统计、浏览器接管、执行策略。

- 主控台内部模块使用 `/?panel=<name>` 地址。
- 在主控台点击普通模块时，前端更新当前面板和 URL，不整页刷新。
- 在统计页点击普通模块时，浏览器直接进入对应主控台模块地址。
- “数据统计”在统计页保持高亮；其他模块在主控台根据 `panel` 参数高亮。
- 浏览器前进、后退必须恢复主控台面板或统计页的原筛选状态。

共享侧栏由单个 Jinja 模板片段生成，主控台和统计页不得维护两套导航文案或顺序。

### 统计内容区

右侧内容区保留现有完整统计能力：

- 顶部显示“TikTok 每日数据”、账号列表、趋势、导入账号、统计设置。
- 数据概览、日期方式、日期范围、账号搜索、账号状态、数据完整度、排序项目、排序方向和分页保持不变。
- 宽表只在表格容器内部横向滚动；页面标题和固定侧栏不随表格滚动。
- 点击账号行在相同内容区进入详情；返回恢复原筛选、页码和滚动位置。
- 趋势与列表在相同内容区切换。
- 导入、Cookie、服务状态和立即采集继续使用弹窗。
- 加载保留页面骨架；错误显示在对应局部区域。

## 实现结构

### 模板和样式

- 新建 `gateway/templates/_dashboard_sidebar.html`，作为唯一侧栏来源。
- 新建 `gateway/static/dashboard_shell.css`，承载共享 `.shell`、侧栏、导航、主内容区和固定侧栏样式。
- `CONTROL_PAGE_HTML` 使用 Jinja `include` 引入侧栏，并在 `render_template_string` 中传入当前外壳上下文。
- `gateway/templates/tiktok_stats.html` 改用同一侧栏和 `.shell`，移除当前独立 `site-header`。
- `gateway/static/tiktok_stats.css` 只负责统计内容组件，不重复定义主控台外壳。

### 主控台导航

侧栏导航统一使用带 `href` 的链接。主控台脚本：

1. 读取 `location.search` 的 `panel`。
2. 验证名称属于已存在面板；非法值回退 `settings`。
3. 普通模块点击时阻止默认跳转，调用现有 `showPanel`，再用 `history.pushState` 写入 URL。
4. 监听 `popstate`，恢复 URL 指定面板。
5. “数据统计”保留正常 `/tiktok-stats` 导航，不由主控台面板代码拦截。

### 删除旧实现

从 `CONTROL_PAGE_HTML` 删除 `panel-publish-stats`，并删除只服务于以下旧 DOM 的事件、渲染和请求代码：

- `stats-filter-date`
- `stats-sort`
- `stats-refresh`
- `stats-count`、`stats-success`、`stats-likes`、`stats-views`、`stats-comments`、`stats-engagement`
- `publish-stats-body`

删除时必须先追踪所有引用；不得影响发布结果、发布采样或新的 TikTok 统计模块。

## 状态和数据边界

- 不修改 `tiktok_stats` API、采集器、调度器、Cookie、安全存储、SQLite 表或保留策略。
- 不修改执行策略、滚动动作和 `config.json` 保存行为。
- 主控台面板状态只写入 URL，不新增持久化文件。
- 统计筛选仍由现有 `tiktok_stats.js` URL 状态管理。

## 错误和可访问性

- 无效 `panel` 参数回退集中配置，不产生空白页或脚本异常。
- 共享侧栏使用导航语义；当前链接设置 `aria-current="page"`。
- 键盘可以聚焦所有导航项；焦点样式与悬停样式清楚区分。
- 小屏幕不隐藏侧栏；允许整个主控台保持最小宽度，统计表格自身横向滚动。
- 统计加载和 API 错误不得遮蔽共享侧栏。

## 测试

### Python 页面测试

- `/` 与 `/tiktok-stats` 包含相同导航文案、顺序和目标地址。
- 主控台初始面板与统计页当前项高亮正确。
- `/tiktok-stats` 仍链接原统计静态资源和完整视图容器。
- 主控台页面不再包含旧统计 DOM ID 或旧卡片文案。

### Node 交互测试

- 合法 `panel` 初始化对应面板；非法值回退 `settings`。
- 点击普通模块更新面板、高亮和 URL，不发起整页导航。
- `popstate` 恢复面板。
- 点击数据统计保留正常路由跳转。
- 现有统计列表、详情、趋势、导入和 Cookie 单向显示测试继续通过。

### 回归

- 运行完整 Python 和 Node 测试。
- 运行 Python、JavaScript 语法检查及秘密扫描。
- 本地页面检查主控台到统计页再返回的连续导航、固定侧栏、表格横向滚动、浏览器前进后退和控制台错误。

## 非目标

- 不把统计接口改成主控台旧发布统计接口。
- 不把整个主控台重写为新的 SPA 或前端框架。
- 不新增侧栏收起、拖拽宽度、主题切换或移动端专用导航。
- 不改变数据统计业务定义或采集周期。
