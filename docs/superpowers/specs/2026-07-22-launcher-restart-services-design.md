# 启动器自动重启服务设计

日期：2026-07-22

## 目标

每次打开启动器：

1. 强制结束所有监听本机端口 `5000` 的进程树。
2. 自动执行现有环境检查。
3. 检查通过后启动当前项目的 Flask 服务和 TikTok 统计 worker。
4. Flask 健康检查通过后打开 `http://127.0.0.1:5000/`。
5. 检查或启动失败时保持服务停止，并在启动器显示原因。

用户已明确授权：端口 `5000` 被其他程序占用时也直接结束，不识别进程来源。终止范围只包含监听端口 `5000` 的 PID 及其子进程，不扫描其他端口或其他 Python 进程。

用户随后确认：非管理员权限不足以强制结束目标时，启动器自动请求 Windows UAC 管理员权限。未提升的父进程退出，由管理员子进程继续完整流程。

## 实现

- 在 `launcher.py` 增加 Windows 端口 PID 查询和强制停止函数。使用 `netstat -ano -p tcp` 查找 `LISTENING` PID，去重后调用 `taskkill /PID <pid> /T /F`，再确认端口已释放。
- `main()` 创建 Tk 窗口前检查管理员权限；未提升时用 Windows `runas` 重新启动同一 `.venv` Python 和 `launcher.py`。管理员进程不重复请求。
- `LauncherApp` 保存 Flask `Popen` 句柄。重复启动前先停止已持有的 Flask 进程和统计 worker，再清理端口 `5000`。
- 启动器界面建立完成后自动触发重启流程；清理和环境检查在线程中执行，不阻塞窗口。
- 复用现有 `run_all_checks()`、`StatisticsWorkerSupervisor` 和环境变量设置，不新增服务注册、PID 文件或常驻管理组件。
- Flask 启动后轮询本机 HTTP；成功才打开浏览器。超时或进程提前退出时显示失败，不打开浏览器。
- 关闭启动器时停止其持有的 Flask 进程和统计 worker。
- 原有“开始检查”和“检查通过后启动”按钮保留，供失败后手动重试；手动启动同样执行先停后启。

## 错误处理

- `netstat` 或 `taskkill` 失败：中止启动并显示最短错误信息。
- 清理后端口仍被占用：中止启动。
- 环境检查存在阻塞项：不启动任何服务。
- Flask 未在限定时间内健康：停止刚创建的 Flask 和 worker，显示启动失败。

## 测试

- 解析一个或多个端口 `5000` 监听 PID，并去重。
- 不处理其他端口、非监听记录和当前启动器 PID。
- 对每个目标使用 `taskkill /T /F`；失败和端口未释放会阻止启动。
- 自动流程顺序固定为：停止旧服务、环境检查、启动 Flask、启动 worker、健康检查、打开浏览器。
- 检查失败和 Flask 健康失败不会打开浏览器。
- 重复启动与关闭都会清理当前进程。

## 非目标

- 不管理 `53330`、`53332` 等调试端口。
- 不安装为 Windows 服务。
- 不引入跨机器服务管理或进程注册中心。
