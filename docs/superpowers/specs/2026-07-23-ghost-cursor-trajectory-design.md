# Ghost Cursor 鼠标轨迹集成设计

## 目标

安装并直接使用 MIT 许可的 `ghost-cursor` npm 包，将现有策略中的“内置拟人函数”替换为 `ghost-cursor.path()` 生成的鼠标轨迹。用户录制的鼠标轨迹保持原有保存格式和执行逻辑。

## 范围

- 移动动作使用 Ghost Cursor 生成内置轨迹。
- 点击动作接近目标元素时使用 Ghost Cursor 生成内置轨迹。
- 已保存且引用 `{"source": "builtin", "id": "bezier"}` 的策略无需迁移；其运行语义自动切换到 Ghost Cursor。
- 策略编辑界面继续显示“内置拟人函数”，不增加新的选择项或保存字段。
- 用户录制轨迹继续引用 `{"source": "pattern", "id": "..."}`，不经过 Ghost Cursor。

不修改元素管理、策略持久化格式、键盘输入、滚动、等待以及录制功能。

## 架构

系统的浏览器执行器使用 Python Playwright，而 `ghost-cursor` 是 Node.js 包。系统增加一个常驻 Node 轨迹生成器，由 Python 包装器按需启动和管理。

数据流：

1. 动作执行器取得当前鼠标位置、目标位置、目标元素尺寸和策略持续时间。
2. Python 包装器通过逐行 JSON 协议向常驻 Node 进程发送轨迹请求。
3. Node 进程调用 `ghost-cursor.path()` 生成坐标点并返回。
4. Python 校验返回数据，将坐标限制在当前页面视口内。
5. Python 按策略采样出的持续时间重新分配轨迹点间隔。
6. 当前 Playwright 页面依次发送 `mouse.move` 事件。
7. 最后一个事件严格使用目标坐标，并更新当前页面记录的鼠标位置。

多个 AdsPower 窗口共享同一个轨迹生成器。每个请求携带唯一编号；Python 包装器保证并发请求不会串用响应。生成过程可以串行化，因为轨迹计算很短，浏览器动作仍由各窗口并发执行。

## Node 进程协议

请求为单行 JSON，包含：

- `id`：请求唯一编号。
- `start`：起点 `{x, y}`。
- `end`：目标点 `{x, y}`。
- `target`：可选目标区域 `{x, y, width, height}`，供 Ghost Cursor 根据目标尺寸生成轨迹。

成功响应包含相同的 `id` 和 `points` 坐标数组。失败响应包含相同的 `id` 和可公开显示的错误信息。协议不传递账号、Cookie、代理或网页内容。

## 参数行为

- Ghost Cursor 负责轨迹形状、速度曲线、过冲和修正点。
- 策略中的“持续秒数”仍是最终移动耗时的唯一控制参数。
- 目标为元素时，最终点必须位于元素当前可见区域内。
- 目标为视口位移时，最终点为裁剪后的视口坐标。
- 所有中间点都裁剪到当前视口边界。
- Ghost Cursor 的随机性保持启用，不新增额外配置项。

## 录制轨迹兼容

当轨迹来源为 `pattern` 时，继续使用现有录制点缩放算法、录制时间间隔和持久化数据。此分支不启动或调用 Node 轨迹生成器。删除或修改录制轨迹的规则不变。

## 生命周期和错误处理

- 第一次需要内置轨迹时按需启动 Node 进程。
- 进程意外退出、响应损坏或通信失败时，Python 终止失效进程、重新启动并重试当前请求一次。
- 重试仍失败时，当前窗口的当前动作失败，错误包含动作编号和 Ghost Cursor 生成失败原因。
- 不静默退回旧贝塞尔算法。
- 一个窗口失败不取消其他窗口的策略执行。
- Python 服务正常退出时结束 Node 子进程，避免残留后台进程。
- 输入、输出和进程错误日志不得包含敏感配置。

## 依赖与许可

- 使用 npm 将 `ghost-cursor` 固定到已验证版本，并更新 `package.json` 和 `package-lock.json`。
- 已安装的 `ghost-cursor` 1.4.2 在 `package.json` 元数据中声明 `ISC`，但包内 `LICENSE` 文件和上游仓库包含 MIT 许可证；此处明确记录该不一致。
- 不修改上游包元数据，也不改写锁文件完整性信息，尤其不得把 `ISC` 元数据静默改写为 MIT。
- 重新分发时必须按包的原始发布形态予以保留，并保留包内及上游的 MIT 版权与许可声明；项目不复制或修改上游源代码。
- 启动器继续使用项目现有 Node.js 环境，不增加用户手工启动步骤。

## 测试

自动测试必须覆盖：

- Node 依赖可加载。
- 轨迹包含多个有限数值坐标点。
- 轨迹首尾和最终落点正确。
- 视口裁剪正确。
- 轨迹总耗时按策略参数缩放。
- 并发请求的编号和坐标不串线。
- Node 进程退出后自动重启并成功重试。
- 第二次失败会返回明确错误，不使用旧算法。
- 录制轨迹不调用 Ghost Cursor。
- 移动和点击的内置轨迹都调用 Ghost Cursor。
- 已保存的旧策略仍可读取和执行。

现有 Python 和 Node 测试必须继续通过。

## 实际验收

1. 打开至少两个 AdsPower 窗口。
2. 两个窗口同时执行包含移动和点击的同一策略。
3. 确认各窗口轨迹独立、动作顺序正确、最终落点位于目标元素。
4. 确认执行结果记录轨迹来源为 `ghost-cursor`。
5. 刷新页面和重启服务后，策略与录制轨迹仍然存在。

## 完成标准

当内置轨迹全部由已安装的 `ghost-cursor` 包生成、录制轨迹保持兼容、常驻生成器可恢复、多窗口测试通过且全部自动测试通过时，本功能完成。
