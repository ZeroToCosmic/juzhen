# 固定评论执行策略设计

## 目标

把自动执行策略收敛为唯一固定流程：

1. 点击评论入口。
2. 输入并验证文案。
3. 点击提交按钮。

移除“有序点击元素”与“输入/提交元素”之间的职责重叠，避免输入框被重复点击、提交按钮在输入前被提前点击。

## 配置模型

自动策略使用三个语义明确的元素字段：

```text
entry_element    评论入口元素别名
input_element    评论输入框元素别名
submit_element   评论提交按钮元素别名
```

`entry_element`、`input_element`、`submit_element` 都必须填写，且三个别名必须互不相同。别名只能来自网页元素模块中已保存的元素。

新的标准配置不再保存 `click_elements`。手动动作策略不受影响。

## 旧策略迁移

加载旧自动策略时接受 `click_elements`，按以下规则迁移：

1. 已有 `input_element` 和 `submit_element` 时，排除二者并对其他别名去重；仅当候选恰好一个时才迁移为 `entry_element`，零个或多个候选都保留为空。
2. `input_element` 和 `submit_element` 都为空、且 `click_elements` 恰好包含三个元素时，按原顺序迁移为入口、输入、提交。
3. 其他无法唯一判断的旧配置不猜测；保留可确认字段，并在界面提示用户补全三个元素后才能保存或执行。
4. 新配置保存成功后只持久化三个标准字段，不再写回 `click_elements`。

迁移只发生在自动策略边界，不修改网页元素或手动动作策略。

## 配置界面

保持现有九步线性页面，调整两处：

- 第 6 步由“有序点击元素”改为“评论入口”，只显示一个入口元素下拉框。
- 第 8 步继续显示输入元素和提交元素。

因此页面顺序直接表达：入口元素 → 文案库 → 输入元素与提交元素。

保存前校验：

- 任一字段为空：提示缺少入口、输入或提交元素。
- 三个字段重复：提示每个职责必须选择不同元素。
- 引用别名已删除：清空失效选择并阻止保存。

网页元素新增、重命名和删除时，三个下拉框立即同步。重命名迁移当前选择；删除清空对应选择。

## 执行流程

每次交互严格执行：

1. 校验入口元素存在且可见，点击一次。
2. 从指定品牌或全部品牌中随机选择一条文案。
3. 校验输入元素存在且可见，点击一次并逐字输入文案。
4. 读取输入控件值及页面回显，确认文案已完整输入。
5. 校验提交元素存在且可见，点击一次。
6. 返回入口点击、输入验证、提交点击三个阶段的结果。

入口失败时不输入；输入或验证失败时不提交；提交失败时整轮交互失败。现有滚动、停留、循环、批量窗口和日志流程保持不变。

## 后端校验与错误

保存和执行前都校验：

- 三个字段存在。
- 三个别名互不相同。
- 三个别名均存在于当前网页元素配置。

错误信息明确指出阶段和别名，例如：

- `自动策略配置校验失败：必须配置入口、输入和提交元素`
- `自动策略配置校验失败：入口、输入和提交元素不能重复`
- `评论入口校验失败：未配置网页元素：评论入口`

任何失败继续按 profile 写入浏览器后台日志，不报告执行成功。

## 测试

采用 TDD，先覆盖失败行为：

1. 运行时严格按入口点击、文案输入、提交点击顺序执行，三个元素各执行一次。
2. 入口失败后不输入、不提交；输入失败后不提交。
3. 保存拒绝空字段、重复字段和不存在的别名。
4. 旧策略三元素列表可自动迁移；不明确的旧列表要求人工补全。
5. 页面不再显示有序点击构建器，只显示入口、输入和提交三个下拉框。
6. 元素新增、重命名和删除会同步三个选择，不覆盖其他未保存字段。
7. 完整 Python 与 Node 测试套件无回归。

## 范围外

- 不支持任意动作编排或多个入口点击。
- 不修改手动动作策略。
- 不修改滚动、文案抽取、批量窗口、AdsPower 或导航逻辑。
