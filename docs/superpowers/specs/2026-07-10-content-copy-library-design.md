# 内容管理文案库改版设计

## 目标

在现有内容管理模块中增加多格式表格导入和品牌文件夹管理。用户可以一次导入多个品牌的文案，系统自动归类、创建缺失品牌、跳过重复文案，并以紧凑的品牌文件夹宫格管理文案。

## 已确认范围

- 支持 `.xlsx`、`.csv`、`.tsv` 三种导入格式。
- 导入字段至少包含品牌名、文案和 Tag，并兼容中文、英文表头。
- 同一文件可包含多个品牌，按品牌字段自动归类。
- 同一品牌下正文和 Tag 完全相同的文案视为重复并跳过。
- 品牌文件夹支持创建、进入查看和重命名。
- 不提供品牌删除，避免误删已被发布任务引用的数据。
- 内容管理页面采用“品牌文件夹宫格”布局。
- 发布模块继续只使用现有的 `brand_id` 和 `copy_id`，不改变发布请求协议。

## 方案选择

对比过三种页面组织方式：左侧文件夹工作区、顶部品牌标签、品牌文件夹宫格。最终选择品牌文件夹宫格，因为它最符合用户对“每个品牌一个独立文件夹”的认知，并能在品牌总览中直观看到文案数量。

导入解析放在 Flask 后端。浏览器只负责选择文件和展示结果，避免在前端分别维护 Excel、CSV、TSV 三套解析逻辑。Excel 使用 `openpyxl` 读取，CSV 和 TSV 使用 Python 标准库 `csv` 读取。

## 数据结构

沿用现有目录结构：

```text
data/content/brands/
  <brand_id>/
    brand.json
    copy.json
```

`brand.json` 保存稳定的内部 ID、可重命名的显示名称和更新时间：

```json
{
  "id": "brand-one",
  "name": "Brand One",
  "updated_at": "2026-07-10T12:00:00+08:00"
}
```

`copy.json` 沿用现有 `items` 数组，每条文案包含 `id`、`body`、`tags`、`created_at`。

品牌重命名只修改 `brand.json` 中的 `name`，不移动目录、不修改 `brand_id`。这样现有发布任务、发布计划和选择器中的引用保持有效。

新建品牌时先使用现有 ASCII `slugify()` 结果；如果名称无法产生有效 ASCII slug，或该 slug 已属于另一个品牌，则使用 `brand-` 加品牌名称规范化后 SHA-256 摘要的前 10 位作为内部 ID。已有品牌 ID 原样保留。品牌匹配按去除首尾空格后的显示名称进行不区分大小写比较。

## 导入规则

### 表头

接受以下表头别名：

| 标准字段 | 中文表头 | 英文表头 |
| --- | --- | --- |
| 品牌名 | `品牌名`、`品牌` | `brand_name`、`brand` |
| 文案 | `文案`、`正文` | `copy`、`body`、`content` |
| Tag | `tag`、`标签` | `tags` |

品牌名和文案为必填；Tag 可以为空。Excel 读取第一个工作表。CSV 和 TSV 接受 UTF-8 BOM。

### 处理流程

1. 根据扩展名选择解析器并读取所有数据行。
2. 规范化表头和单元格字符串，记录原始行号。
3. 将有效行按品牌名分组。
4. 匹配现有品牌；不存在时创建品牌目录。
5. 对每个品牌读取一次现有文案，按“去除首尾空格后的正文 + 规范化 Tag 列表”判断重复。
6. 将新增文案一次写回对应品牌的 `copy.json`。
7. 返回导入统计和逐行失败信息。

Tag 使用现有 `parse_tags()` 规则拆分。去重比较时保留正文内容，只去除正文首尾空格；Tag 去除空白后按原顺序比较。同一导入文件内部的重复项也会被跳过。

无效行不会中断整批导入。无法识别文件格式、缺少必要表头或文件本身损坏时，整次请求失败且不写入数据。

## 后端接口

### `GET /api/content/brands`

在现有品牌列表中增加 `copy_count` 和 `updated_at`，供文件夹宫格展示。

### `PATCH /api/content/brands/<brand_id>`

请求：

```json
{
  "name": "新的品牌名称"
}
```

只更新显示名称。品牌不存在返回 404；名称为空或与其他品牌重名返回 400。

### `POST /api/content/copy/import`

使用 `multipart/form-data` 上传字段 `file`。成功响应：

```json
{
  "total": 12,
  "created": 8,
  "duplicates": 2,
  "failed": 2,
  "brands_created": 1,
  "brand_results": [
    {
      "brand_id": "brand-one",
      "brand_name": "Brand One",
      "created": 5,
      "duplicates": 1
    }
  ],
  "errors": [
    {
      "row": 7,
      "error": "缺少文案"
    }
  ]
}
```

单个失败行不包含原始文案全文，避免错误响应过大。

## 页面设计

内容管理页面分为两个连续区域，不嵌套卡片：

1. 视频内容库：使用紧凑统计行显示总数、可用、已使用，保留同步和刷新操作。
2. 文案库：默认显示品牌文件夹宫格，顶部只保留“新建品牌”和“导入表格”。

每个品牌文件夹显示品牌名、文案数量和最近更新时间。点击文件夹后在当前面板进入品牌详情，不打开新页面。

品牌详情包含返回按钮、品牌名称、重命名按钮、紧凑的手动添加表单和文案表格。表格列为正文、Tag、创建时间。页面不显示运行控制台。

导入表格使用弹窗。文件提交成功后显示新增、重复、失败和新增品牌数量；存在错误行时提供可展开的行号与失败原因列表。导入完成后刷新品牌宫格，当前品牌详情保持可用。

宽屏使用自适应宫格，窄屏改为单列文件夹列表。输入框、按钮和间距使用统一紧凑尺寸；命令使用文字配合 Lucide 图标，页面文案保持中文。

## 模块边界

- `gateway/content_import.py`：只负责读取三种文件格式、表头映射和输出标准行数据。
- `gateway/content_store.py`：负责品牌查找、稳定 ID、批量写入、去重、统计和重命名。
- `gateway/app.py`：负责 HTTP 参数、状态码和页面交互，不包含文件格式解析细节。

## 错误处理

- 不支持的扩展名：400，提示支持的文件格式。
- 空文件、缺少必要表头、损坏的 Excel：400，不写入任何品牌或文案。
- 单行缺少品牌或文案：跳过该行，在结果中记录行号和原因。
- 重命名为空或与其他品牌重名：400，保留原名称。
- 品牌不存在：404。
- 文件上传上限为 10 MB，超限时返回中文错误，不把文件内容写入日志。

## 测试

- 解析测试：`.xlsx`、`.csv`、`.tsv`，中文和英文表头，UTF-8 BOM。
- 导入测试：同文件跨品牌归类、自动创建品牌、中文品牌 ID、文件内重复、与已有数据重复、Tag 规范化。
- 错误测试：空文件、错误扩展名、缺少表头、损坏 Excel、空品牌、空文案。
- API 测试：上传响应统计、品牌统计字段、重命名成功、重名失败、品牌不存在。
- 页面测试：宫格入口、导入控件、品牌详情、重命名操作、中文文案和紧凑布局标识。
- 回归测试：原有手动添加文案、手动发布、批量发布和定时计划继续按现有 ID 工作。

## 验收标准

- 一份包含多个品牌的 Excel、CSV 或 TSV 文件可一次提交并正确归类。
- 缺失品牌会自动建立独立目录，已有品牌不会重复建立。
- 重复文案不会写入，导入统计与实际文件内容一致。
- 品牌可进入查看和重命名，但没有删除入口。
- 页面在桌面和窄屏下无重叠、无横向溢出，表单比现有页面更紧凑。
- 全部新增测试和原有测试通过。
