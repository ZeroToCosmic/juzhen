# 本机直开模式恢复原管理后台设计

## 目标

修复 `LOCAL_DIRECT_MODE` 把根地址 `/` 替换成 V2 独立页面的问题。本机启动器打开的首页恢复为原管理后台，V2 继续通过 `/browser-v2` 独立访问。取消账号密码登录和仅允许本机访问的现有行为保持不变。

## 已确认根因

启动器按设计设置 `LOCAL_DIRECT_MODE=1`。`gateway.app.dashboard_page()` 在该模式下直接返回 `browser_v2.html`，导致完整的 `CONTROL_PAGE_HTML` 永远不会在根地址渲染。原后台模板、侧栏、模块、接口和数据没有被删除，只是入口被替换。

## 方案比较

选择方案：恢复 `/` 为原后台，保留 `/browser-v2`，并在原后台侧栏增加 V2 入口。这符合用户原有访问习惯，改动最小，两个页面继续保持独立。

未选择方案：把原后台迁移到 `/dashboard` 并保持 V2 为首页。该方案仍改变原入口，不符合恢复要求。未选择把 V2 嵌入原后台单个面板，因为会重新耦合独立模块并扩大回归范围。

## 路由与会话设计

本机直开模式继续安装 `install_local_only_guard(app)`，拒绝非回环地址或非本机 Host。增加一个仅在本机直开模式注册的 `before_request`：当会话没有有效 `csrf_token` 时生成并保存随机 token。它只为原后台页面和 `management_fetch.js` 提供一致的页面上下文，不重新启用账号登录。

根路由在两种模式下都渲染现有 `CONTROL_PAGE_HTML`：

- 本机直开：使用刚初始化的 CSRF token，无登录跳转；
- 传统管理模式：继续使用认证守卫创建的 CSRF token，不改变登录与权限行为。

`/browser-v2` 继续渲染 `browser_v2.html`。传统管理模式下它仍受原认证守卫保护；本机直开模式下受本机访问守卫保护。

## 导航设计

在 `_dashboard_sidebar.html` 增加普通链接“浏览器执行策略 V2”，目标为 `/browser-v2`。该链接不设置 `data-panel`，避免旧后台的面板切换脚本把它当作内嵌面板处理。现有“执行策略”入口和原有模块不删除、不改名。

## 安全与错误边界

- 不恢复账号密码登录；
- 不允许局域网或外部 Host 访问本机直开页面；
- 不修改旧后台 API、V2 API 或数据存储；
- 不把 V2 HTML 注入旧后台；
- CSRF token 不写日志、不放入 URL；
- 传统认证模式行为保持原样。

## 测试与验收

自动测试验证：

1. 本机直开访问 `/` 返回原后台标识 `dashboard-shell`，不包含 `browser-v2-app`；
2. `/browser-v2` 仍返回 `browser-v2-app`；
3. 根页面包含 `/browser-v2` 侧栏入口；
4. 本机直开会话包含非空 CSRF token；
5. `/login` 仍为 404；
6. 外部 Host、非回环地址和错误端口仍返回 403；
7. 传统模式仍要求登录；
8. V2 Python、V2 Node、认证和页面相关测试全部通过。

页面验收验证启动器重启后 `http://127.0.0.1:5000/` 显示原管理后台全部菜单；点击“浏览器执行策略 V2”进入独立 V2 页面；浏览器后退可返回原后台。
