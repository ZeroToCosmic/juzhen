# Selector 设置保存原因弹窗修复设计

日期：2026-07-30

## 问题

新增 AdsPower 测试 Profile 属于危险设置变更。现有前端在原因为空时直接返回，只把 `reason_required` 显示在设置页顶部；用户位于页面底部，看起来像按钮无响应。设置确认弹窗还把原因输入框强制隐藏。

## 设计

- “检查并保存”继续执行候选设置校验。
- 危险变更缺少原因时，不再阻止确认弹窗打开。
- 设置确认弹窗在存在危险变更时显示必填“危险变更原因”。
- 页面已有原因值作为弹窗初始值；用户也可直接在弹窗中填写。
- 点击“确认保存”时再次检查原因；为空则在弹窗内显示中文提示，不发送 PATCH。
- 原因有效后写入同一个设置 PATCH，保持后端审计要求不变。
- `target_origin_invalid`、`preflight_required`、`preflight_failed`、草稿过期等不能进入确认阶段的错误，在“检查并保存”按钮旁显示中文提示。
- 保存失败时弹窗保持打开，暂存 Profile 和原因不丢失。

## 范围

仅修改设置保存前端交互与相关测试。不降低后端危险变更规则，不修改 Profile 批量保存 API，不改其他确认弹窗。

## 验收

1. 暂存测试 Profile 后，无须预先找到页面原因框。
2. 点击“检查并保存”打开确认弹窗并显示原因输入框。
3. 原因为空时弹窗内明确提示，不发送 PATCH。
4. 填写原因后可提交，PATCH 包含原因和全部暂存 Profile。
5. 保存失败后可原样重试。
