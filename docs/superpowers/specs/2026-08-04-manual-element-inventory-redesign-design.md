# 人工元素目录与探针精简设计

## 背景

现有探针先提取 A11y 快照，再用语义契约把候选节点匹配为“评论入口、评论输入框、评论提交按钮”。最新第 28 次运行已读取 50 个候选元素，其中 46 个具有定位路径，但旧语义契约仍以 `zero_match` 结束整个运行。因此故障不是页面没有元素，而是自动语义分类拒绝了已读取元素。

本设计删除语义匹配和 LLM 选择器生成。探针改为展示当前页面全部可见交互元素，由管理员人工选择、命名并记录到元素目录。系统继续负责确定性路径生成、Dry-Run、双 Profile 双轮验证、原子发布、健康检查、影响隔离和告警。

## 已批准目标

- 扫描当前页面全部可见交互元素，不再只寻找预定义关键元素。
- `Role` 和 `Name` 仅作为只读说明，不参与匹配、验证、自愈或页面跳转。
- 管理员可从精简元素列表中勾选、批量命名、编辑、重新绑定和删除元素。
- 采集时记录管理员的真实点击步骤；每日探针重放这些步骤后验证二级页面元素。
- 只使用确定性 CSS/XPath；不调用 LLM，不使用反馈式 Prompt 自愈。
- 元素失效后发送截图告警，只暂停引用该元素的策略。
- 保留双 Profile、连续两轮一致、三次重试、原子发布、上一稳定版、自动恢复和人工暂停/恢复。
- 一级菜单从七项精简为“采集元素、已选元素、运行与告警、系统设置”。
- 旧元素保留名称和策略引用，但统一迁移为“待重新绑定”。

## 非目标

- 不自动判断元素是否为评论入口、输入框或提交按钮。
- 不根据文字、Role、Name、页面位置或截图直接执行点击。
- 不扫描不可见布局节点、纯样式容器或整个原始 DOM。
- 不恢复绝对 XPath，不直接把未经验证的草稿写入 Redis。
- 不删除双 Profile、版本、策略暂停或审计能力；这些能力只从一级菜单移入相关详情。

## 总体流程

```text
打开独立测试 Profile
  -> 管理员手动操作页面
  -> 扫描当前可见交互元素
  -> 勾选并自定义命名
  -> 生成确定性 CSS/XPath
  -> 当前窗口 Dry-Run
  -> 保存待验证草稿
  -> 两个 Profile 各验证两轮
  -> 原子发布到 Redis
  -> 每日 03:00 健康检查
```

采集窗口由管理员显式关闭、取消、超时或发生致命错误后关闭。扫描、选择或单次 Dry-Run 完成不会提前关闭窗口。

## 元素扫描

### 范围

扫描当前渲染页面中的可见交互元素：

- `a`、`button`、`input`、`textarea`、`select`、`option`、`summary`；
- `contenteditable`、有效 `tabindex`；
- 含 `data-e2e`、`data-testid` 等稳定测试属性的可见节点；
- 具有原生点击行为、点击监听器或指针交互特征的可见容器。

扫描主文档、同源 iframe 和开放 Shadow DOM。跨源 iframe 仅在现有 CDP 执行上下文允许时独立扫描，不绕过浏览器安全边界。

嵌套节点映射到同一点击目标时只保留最接近真实交互目标的记录。单次最多返回 500 项；超过上限时按可定位性、交互确定性、视口距离排序，并明确显示已截断。

### 精简投影

浏览器外只返回：

- 临时选择 ID；
- 标签、输入类型、文本摘要；
- 只读 `Role`、`Name`；
- 允许列表内的稳定属性；
- 所属 frame、Shadow DOM 标记；
- 归一化边界框和页面区域；
- 可见、可用、可定位状态；
- 候选 CSS/XPath 与当前匹配数量。

不返回原始 HTML、完整 DOM、CDP 地址、后端节点 ID、未脱敏 Profile ID、Cookie、Token 或表单内容。

## 操作记录与页面状态

采集过程分为“浏览”和“选择”两个状态。浏览状态允许管理员正常点击页面；每次实际点击记录目标的确定性路径和顺序。管理员完成页面操作后点击“重新扫描当前页面”，系统保存本次扫描与此前点击步骤的关系。

记录的自动重放动作仅包括点击。探针负责把目标滚动到视口，不保存固定滚动坐标。每一步点击后等待：

- 文档处于 `interactive` 或 `complete`；
- DOM 和候选数量连续采样保持稳定；
- 下一扫描中保存的目标路径出现，或达到 90 秒上限。

系统不根据按钮文字、Role、Name 或预定义页面状态推断下一步。点击步骤失效时，该步骤及其下游元素均记为失败，并沿用相同的重试、告警和影响隔离规则。

## 确定性选择器

候选路径按以下顺序生成：

1. 唯一 `data-e2e`、`data-testid` 或其他允许列表内测试属性；
2. 非动态且唯一的 `id`；
3. 唯一 `name`、`placeholder`、`aria-label`、`contenteditable`、`type` 组合；
4. 稳定父级属性加短子节点路径；
5. 短 `nth-of-type` 路径。

每个元素同时生成 CSS 和 XPath，最多保留六条。禁止绝对 XPath、长索引链、随机类名、文本内容定位和坐标点击。

每条路径在进入草稿前必须：

- 匹配数量恰好为 1；
- 匹配原始选中节点；
- 节点可见且未禁用；
- 通过中心点命中检查；
- 不依赖 `Role` 或 `Name`。

页面位置只用于列表展示、指纹差异和人工重新绑定参考，不用于自动点击。

## 数据模型

新的受管元素记录包含：

- `element_id`、`display_name`；
- `status`：`pending_rebind`、`draft`、`validating`、`healthy`、`degraded`、`invalid`；
- 目标 origin、URL 规则和采集页面标识；
- 操作步骤链；
- 标签、稳定属性、DOM 祖先摘要、归一化位置指纹；
- 主 CSS/XPath 和已验证备用路径；
- 当前版本、上一稳定版本；
- 引用该元素的策略；
- 最近成功、失败、截图告警和验证证据引用。

现有 `strategy_dependencies`、版本、闸门原因、运行记录和审计记录继续使用。`element_probe_contracts` 中的语义字段不再进入运行时；迁移完成且所有调用点移除后删除语义契约存储和对应 API/UI。

## 旧数据迁移

升级时把现有元素的 ID、显示名称和策略引用迁入新受管元素记录。旧语义契约、语义别名和未验证语义候选不迁入定位路径。

所有旧元素初始状态为 `pending_rebind`。引用它们的策略保持暂停，管理员从新扫描列表重新绑定后进入双 Profile 双轮验证。验证和原子发布成功后，系统才允许自动恢复非人工暂停策略。

迁移具备幂等性；重复启动不得重复创建元素、策略依赖或暂停原因。

## 保存与发布

当前采集窗口 Dry-Run 成功后只保存“待验证草稿”。后台使用两个独立 AdsPower 测试 Profile，各运行两轮。每轮重放操作步骤并检查每条路径唯一、可见、可操作。

四次结果一致后，通过现有原子发布边界一次写入新版本和 Redis `validated_selectors`。发布失败时保留上一稳定版本，草稿保持未激活，不恢复任何策略。

## 每日健康检查

每天 03:00 验证所有已发布受管元素：

1. 准备两个独立 Profile 和各自页面；
2. 重放元素所属页面的操作步骤；
3. 每个 Profile 连续验证两轮；
4. 汇总元素级结果；
5. 原子发布已验证的路径切换或恢复；
6. 发送告警并清理窗口、页面和租约。

主路径失效但已保存备用路径四次均唯一命中时，元素标记为 `degraded`，不暂停策略；备用路径原子升级为主路径后恢复 `healthy`。系统不会现场生成新路径。

所有保存路径均为零匹配、多个匹配、不可见或不可操作时，刷新页面并重试，最多三次。仍失败则元素标记为 `invalid`，保存现场截图，发送后台告警和可配置 Webhook，只暂停直接或间接引用该元素的策略。

## 恢复规则

旧路径重新有效或管理员完成重新绑定后，必须同时满足：

- 至少两个独立测试 Profile 通过；
- 每个 Profile 连续两轮结果一致；
- 新版本原子发布成功；
- 相关元素不存在其他未解决自动暂停原因。

满足后仅自动恢复受本元素影响、且没有人工暂停原因的策略。人工暂停永不由自动流程清除，后台始终保留人工暂停/恢复开关。

## 管理界面

### 采集元素

显示四步流程：打开页面、手动操作、扫描当前页面、命名并保存。列表支持按按钮、输入、链接、页面区域和可定位状态筛选。右侧编辑区显示自定义名称、操作步骤、CSS/XPath、Dry-Run 结果和“检查并保存”。

### 已选元素

显示自定义名称、页面位置、健康状态、主路径和受影响策略。支持编辑名称、重新绑定、删除、查看截图和展开详情。备用路径、双 Profile 两轮证据、历史版本、策略暂停原因和人工恢复放入详情。

删除仍被策略引用的元素前，必须明确列出影响并要求先移除引用；不允许静默留下悬空策略依赖。

### 运行与告警

合并原“探针运行”和“告警”。一次运行默认只显示：准备测试环境、打开页面并重放操作、验证已选元素、保护或恢复相关策略、发送告警并清理。CDP、租约、发布事务和重试明细放入可展开“诊断详情”。

旧 `publish`、`reconcile`、`cleanup`、`lease` 等字段不得作为无解释的主界面文案。

### 系统设置

保留测试 Profiles、每日时间、目标网页、页面等待、Webhook、Redis 和权限控制。删除 LLM 模型、API Key、Prompt 版本及语义契约默认值。

原“总览”变为四个菜单顶部摘要；“策略闸门”和“版本”移入元素或运行详情，不再作为一级菜单。

## 权限与安全

- 采集、保存、编辑、重新绑定、删除、人工暂停和恢复仅管理员可操作。
- 操作员可查看元素状态、运行记录、告警和诊断详情，并可按现有权限确认告警、立即运行探针。
- 所有写操作保留 revision/预检/审计边界，避免并发覆盖。
- Profile ID、CDP 地址、Redis 密码、Webhook 秘密和页面敏感内容继续脱敏。
- 选择器和操作步骤均视为不可信输入，在服务端执行长度、类型、属性允许列表和作用域校验。

## 删除范围

实现完成后删除或停止暴露：

- 运行时语义契约加载、种子数据和候选筛选；
- `accepted_roles`、`accepted_names`、语义 intent、语义 scope、语义 position hint；
- LLM 选择器生成、反馈式 Prompt 修正和模型配置；
- 语义契约新增、编辑、删除界面与接口；
- 以固定“评论入口/输入框/提交按钮”为成功前提的阶段；
- UI 中无解释的七标签和技术状态摘要。

允许保留 A11y 提取能力用于生成只读 `Role/Name` 展示，但其输出不得进入匹配分数、路径选择、Dry-Run 判定或操作重放。

## 失败处理

- 页面在 90 秒内未稳定：`page_inventory_timeout`，保留窗口现场截图后清理。
- 扫描结果为空：`page_inventory_empty`，不尝试语义修正。
- 点击步骤路径失效：`recorded_step_unavailable`，下游元素失败并隔离相关策略。
- 路径零匹配：`selector_zero_match`。
- 路径多匹配：`selector_ambiguous`。
- 原子发布失败：`selector_publish_failed`，继续使用上一稳定版本。
- 第二 Profile 或第二轮失败：草稿不激活，相关策略不自动恢复。

所有失败都必须显示中文原因、影响元素、受影响策略、已执行保护动作和下一步处理方式。

## 测试与验收

### 单元测试

- 交互元素扫描、可见性、嵌套去重、iframe/Shadow DOM 投影和 500 项上限；
- 稳定属性排序、动态 ID 排除、CSS/XPath 生成和绝对 XPath 禁止；
- `Role/Name` 改变不影响候选路径和验证结果；
- 点击步骤记录、净化、重放和 90 秒超时；
- 旧元素幂等迁移为 `pending_rebind`；
- 元素级策略影响计算和人工暂停保护。

### 集成测试

- 已发现的 50 个元素能直接进入列表，不再因三个旧语义别名失败而丢弃；
- 选择、命名、编辑、重新绑定、删除完整闭环；
- 当前窗口 Dry-Run 成功后只创建草稿；
- 双 Profile 双轮一致后原子写入 Redis；
- 主路径失败、备用路径成功时完成降级与原子切换；
- 所有路径三次失败后截图告警并只暂停相关策略；
- 两个 Profile 两轮通过且发布成功后只恢复非人工暂停策略；
- 发布失败、窗口清理失败和租约失败均保留可诊断记录。

### UI 验收

- 只有四个一级菜单，模块边界和上下级关系清晰；
- “采集元素”可显示、筛选和选择当前页面元素；
- “已选元素”可看到名称、路径、状态和策略影响；
- “运行与告警”默认显示五个业务步骤，技术字段位于诊断详情；
- “系统设置”不再出现 LLM、API Key、Prompt 或语义契约；
- 桌面宽度和窄屏下均能完成核心操作；
- 关键按钮、状态和错误具备可访问名称与键盘操作。

## 完成判定

只有当旧语义匹配不再参与运行、人工元素采集闭环可用、旧元素安全迁移、双 Profile 双轮发布成功、失效隔离与恢复测试通过、四菜单 UI 验收通过时，本改造才算完成。
