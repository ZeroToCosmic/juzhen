# 执行策略元素选择同步设计

## 目标

自动执行策略的“输入元素”和“提交元素”只能从“网页元素”模块中已添加的元素别名里选择。网页元素新增、重命名或删除后，相关下拉框立即同步，无需重新读取配置或刷新页面。

## 根因

网页元素保存后，页面只重绘元素列表和策略表单，没有重建自动策略的元素下拉选项。现有完整刷新函数虽然能重建选项，但同时会重新渲染当前策略，可能覆盖用户尚未保存的表单内容。

## 设计

新增一个只负责同步元素选项的前端函数，更新以下控件：

- 输入元素下拉框
- 提交元素下拉框
- 有序点击元素选择框

同步规则：

1. 选项来源仅为当前 `browserActionConfig.elements` 的别名。
2. 当前选择仍存在时保留。
3. 元素重命名时，使用旧别名的控件自动切换到新别名。
4. 元素被删除且当前选择失效时，输入元素和提交元素清空；有序点击选择框回到提示项。
5. 同步选项不重绘自动策略其他字段，不覆盖未保存内容。

元素新增、重命名、删除，以及服务端保存网页元素配置成功后，调用该同步函数。现有后端接口、配置字段及执行逻辑保持不变。

## 错误处理

没有可用网页元素时，输入元素和提交元素显示空提示项并保持不可选值为空。后端现有校验继续阻止执行引用缺失元素的策略。

## 测试

先增加失败测试，覆盖：

- 输入元素和提交元素来自网页元素别名。
- 新增元素后选项立即出现。
- 重命名元素后当前选择迁移到新别名。
- 删除已选元素后选择清空。
- 同步元素选项不会改动策略表单其他值。

实现后运行相关前端/页面测试，再运行完整测试套件。

## 范围外

- 不允许手动输入任意元素别名。
- 不修改 XPath 编辑方式。
- 不修改自动策略配置格式或浏览器执行逻辑。
