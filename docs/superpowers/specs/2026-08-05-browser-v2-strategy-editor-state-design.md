# Browser V2 策略编辑器状态修复

## 问题

活动点选器或任务每秒轮询一次。轮询完成后调用全页 `render()`，`renderStrategies()` 重建策略表单及全部动作输入节点。

策略名称、目标网址、就绪元素、就绪超时、分钟范围和启用状态没有完整写回 `state.draft`。重绘后，这些字段恢复旧值。动作参数虽写回草稿，但节点被重建后持续失去输入焦点。未完成字段触发的保存校验信息继续保留，形成页面一直报错的观感。

## 选择

采用方案 A：策略草稿实时同步，活动轮询局部刷新。

不采用：

- 活动任务期间禁止编辑：限制正常使用。
- 重构完整表单状态系统：范围过大。

## 实现

只修改 `gateway/static/browser_v2.js`：

1. 为策略名称、目标网址、就绪元素、就绪超时、分钟范围和启用状态绑定 `input` 或 `change` 事件，实时更新 `state.draft`。
2. 运行方式继续写入草稿并仅更新分钟范围显隐，不重建整个策略编辑器。
3. `refreshActive()` 完成轮询后仅更新任务区域、点选器区域和状态信息，不再调用全页 `render()`。
4. 保存策略仍使用现有序列化和校验，不改变 API 请求结构。
5. 增删、移动动作时允许 `renderStrategies()` 重建列表；因所有策略字段已经写入草稿，值不会丢失。

不修改 HTML、API、数据库、后端校验或其他页面。

## 验收

- 活动点选器连续轮询后，就绪元素保持选中。
- 分钟范围输入后连续轮询，值不清空、焦点不丢失。
- 动作参数输入时连续轮询，输入节点不被替换。
- 新增、删除或移动动作后，策略顶部字段保持原值。
- 不点击“保存策略”时，不产生策略校验错误。
- 现有 Browser V2 UI 测试全部通过。
