# Browser V2 点选器点击捕获最小修复

## 问题

点选器在 `pointermove` 时保存高亮节点，`click` 时直接使用该旧引用。TikTok React 重渲染或鼠标路径变化后，用户点击评论提交按钮，实际提交给后端的节点可能不是点击路径中的按钮。后端随后拒绝错误节点的定位器。

现场只读验证确认真实评论提交按钮有效：`button[data-e2e="comment-post"][aria-label="Post"]` 唯一、可见、启用；CSS、ARIA、XPath 候选均通过严格校验。

## 选择

采用核心最小方案：只修正浏览器内点击捕获，不新增接口、不改数据库、不改后端校验规则。

未采用：

- 同时扩展后端细分错误码：有诊断价值，但不是恢复本次点击捕获的必要条件。
- 重做点选会话协议：范围过大。

## 实现

在 `execution_v2/picker_overlay.js` 的捕获阶段：

1. 收到 `click` 后重新读取 `event.composedPath()`。
2. 使用 `resolveActionable(path)` 获取点击瞬间的可操作祖先。
3. 仅当节点存在且仍连接当前 DOM 时捕获。
4. 使用该节点更新 `active` 并生成选择记录；不再依赖上一次 `pointermove` 保存的节点。

不改变选择器生成、严格 Dry-Run、保存格式或 UI。

## 验收

- 鼠标先悬停其他节点，再直接点击按钮内 SVG：保存按钮，不保存旧高亮节点。
- 点击路径中的按钮发生替换时：捕获新按钮。
- 点击路径没有可操作祖先时：保持现有普通元素选择能力。
- 现有点选器 Node 测试全部通过。
